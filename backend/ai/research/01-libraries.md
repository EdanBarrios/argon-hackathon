Each of the above meets the criteria: they parse or compress input from stdin deterministically, have known test corpora or built-in tests, and have had memory-safety issues (CVE’s) exploitable under ASan. All use permissive licenses and compile with plain C (e.g. clang).  For example, **SQLite** is a large self-contained C library (amalgamation ~200K lines) with a release as recent as 2026-10-16 (public-domain license). Its CLI `sqlite3` can take SQL scripts on stdin and print text output, and it includes an extensive test suite. It has known CVEs (e.g. a 2020 heap overflow). It has no pure-Rust port, so it’s a strong migration candidate. 

**LibYAML** (release 0.2.5 on 2020‑06‑01, MIT license) is a C library for YAML parsing/emitting. It comes with example emitter CLI tools and tests (and even an OSS-Fuzz target), and had at least one buffer-overread CVE. **Jansson** (last updated July 2026, MIT) is a JSON encoder/decoder with an *extensive test suite*. Although it lacks a default CLI, one can easily write a small program for stdin→stdout JSON handling. It has had no recent CVEs and no known Rust port. **YAJL** (ISC license) is a small event-driven JSON parser/generator. It includes example CLI tools like `json_reformat` and a test directory. We marked some CVEs (e.g. a 2019 heap issue) [unverified], but it qualifies by size and determinism. **zlib** (zlib license) is the classic compression library, version 1.2.11 released in 2017. Its `minigzip` tool handles stdin→stdout, it has a built-in test suite, and known CVEs (deflate bugs) exist. It too has no direct Rust port (only wrappers). 

**Best Next Target (after cJSON):** Based on coverage of domains and missing test saturation, **LibYAML** stands out. It is the canonical C YAML library (widely used in applications for config files) and satisfies all criteria: a 3K‑line C codebase (0.2.5, 2020), YAML parser/emitter semantics on stdin, an MIT license, built-in tests/regression inputs, and past CVEs. Its functionality is complementary to JSON (tested by cJSON), and there is no mature pure-Rust equivalent, making it a rigorous new migration target.

**C2Rust/CRUST/TRACTOR Resources:**  The **CRUST-Bench** dataset contains 100 C repositories with paired Rust interfaces and test cases, which provides programs and tests (GPLv3) that could help assess transpilation. DARPA’s **TRACTOR** public test corpus (GPLv3) supplies C programs and evaluation scripts. These include runnable C examples and input vectors that we could reuse (programs and tests, not directly the libraries above). They offer benchmarks and metrics (pass/fail, performance) but no new criteria beyond what the above libraries provide.
