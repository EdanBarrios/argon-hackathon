# 04: Stage Q&A (owner: Brendan, AI)

Three answers, each about 30 seconds spoken, then the facts for follow-ups. Every number
traces to a file in backend/ai/results/.

## 1. "Why did libexpat use 815K input tokens when the library is about 200K?"

**Say:** "Because of how long replies are generated. Argon writes in segments of about 65K
tokens, and each new segment re-reads the whole prompt plus everything it has written so far.
Our prompt was 206K tokens. The reply was 131K tokens, thinking plus code, so it took three
segments: three reads of the prompt, plus re-reading its own first two segments. That adds up
to 815,575. The API reported 815,566, so we're within 9 tokens. The same formula fits both
repair calls within 79 tokens."

**Follow-ups:**
- Source: the interaction's stored steps plus `count_tokens`. Script:
  `results/expat-long-decode/token_accounting.py`, output in `token_accounting.txt`.
- It is our reconstruction from the numbers, not a documented API rule. Say so if asked.
- Every segment boundary is at exactly 65,563 generated tokens, close to the 65,536 output cap.
- Cost: input $1.63 for that call instead of $0.41 for one read (at $2 per 1M).
- Caching works across calls: the second fresh repair had 554,740 of its 626,150 input tokens
  cached, because its prompt shared a prefix with the first.
- Likely link: the one repair that failed over `previous_interaction_id` stopped at 65,416
  output tokens, as if a follow-up turn cannot start a second segment. Not confirmed.

## 2. "What did the two compile fixes change?"

**Say:** "Three lines out of 6,555, in the port of expat's storeAtts, which processes attributes and rejects duplicates. The
first was a missing type: the compiler couldn't infer what a vector holds, so Argon wrote
`Vec<usize>`. The second was a borrow error: the loop borrowed the attribute list, but the
error path hands that list back to the parser while still reading the current attribute.
Argon switched to copying each attribute out by index, so the borrow ends each iteration.
Neither fix changed behavior. The first build already matched every one of the 747 loop
inputs, then 1,253 of 1,253 held-out, and the host re-verified 2,000 of 2,000 on a fresh seed."

**Follow-ups:**
- Errors: E0282 at `expat.rs:5967` (round 1), then E0505 at `expat.rs:5969` (round 2). rustc
  only reports borrow errors after type checking passes, which is why it took two rounds.
- rustc's own hint for E0505 was `&raw_atts.clone()`. Argon copied one attribute per
  iteration instead, which avoids cloning the whole list.
- Diff: `results/expat-long-decode/argon-fresh-a/round1_to_round3.diff`. Each repair was a
  fresh call with the C source, the previous file and the compiler output, at thinking medium.
- Run `argon-fresh-b`, same settings, returned the file unchanged in its round 2. A repair
  is not guaranteed to make progress.

## 3. "What does the quality gate check?"

**Say:** "Three tool checks on every build that compiles, with no model judgment: rustfmt,
cargo clippy at its default lints, and clippy's restriction lints for code that can panic,
meaning indexing, slicing, unwrap, expect and panic. First the host applies clippy's own
auto-fixes and keeps them only if a rebuild and reverify show identical behavior. Whatever is
left goes back to Argon as a polish round. Behavior always ranks first, so a cleaner file that
changes a single output is never the one we keep. On cJSON that gave zero clippy warnings and
zero panic sites, still matching 763 of 763 unseen inputs."

**Follow-ups:**
- It caught a real one: polishing an older port removed all lints but broke `\t` and `\r`
  escaping on 6 of 300 inputs. The gate rejected it.
- `unsafe` is rejected by the build itself, so the gate doesn't need to look for it.
- Overflow lints (`arithmetic_side_effects`, 40 in the cJSON port) are reported, not gated.
  Most are bounded `i += 1` steps, and forcing them to zero pushes code toward wrapping math
  that can change behavior.
- Proof: `results/cjson-quality/`. `recheck.py` imports nothing from our loop, rebuilds from
  scratch, reruns the verifier and recounts lints. All 13 claims hold.
- **It is cJSON only, and one run.** The libexpat port has not been through the gate. Measured
  as-is: 1 clippy warning (`too_many_arguments`), 154 panic lints (153 indexing, 1 unwrap),
  491 overflow lints, not rustfmt-formatted. If asked: "Not yet. Its behavior is verified, its
  lint count isn't clean."
- Don't use the targeted 980/980 as an Argon vs Flash point: Argon also misses the same 19
  inputs in 3 of 4 earlier ports.
